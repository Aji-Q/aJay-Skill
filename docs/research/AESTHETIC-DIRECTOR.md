# 独立用户代表 / 美学总监评审

日期：2026-09-09。范围：旧预览实看 + 下一版方案建议；未编辑前端。本文是验收标准，不是对实现的认可。

## 1. 已观察到的事实

独立浏览器标签访问 `http://127.0.0.1:8787/AJAY.DEMO_20260909/full-report-standalone.html`；实看 1280×720 首屏、首屏之后、Buffett/Simons 肖像区域，并读取页面语义结构。

- 首屏是居中胶囊导航、左侧公司名/简介/价格/CTA、右侧曼哈顿天际线。这是金融品牌落地页结构，用户在“看网站”，不是“进入研究现场”。
- 城市是远距离全景，统一蓝黑蒙版压暗。建筑大量等亮窗格与水面高光形成素材壁纸感；它没有近景、尺度参照或室内外关系。仅从截图不能断言每一处生成缺陷，但页面明确标注 AI-GENERATED COVER。
- 下一屏先遇到 100%、90%、审阅状态和时间，再遇到紫色兜底识别横条，再到“核心结论”。事实边界值得保留，但核心问题被流程诊断截断。
- 黑白 Buffett / Simons 半身肖像具有真实的视觉重量、留白和层次，是当前最成功部分。然而两张并列矩形只附姓名与口号，没有连接具体判断，更没有反证。
- 后续为维度块、分歧块、流派评分、66 个席位、66 条笔记的长页面。大量缺失/不适用内容仍占据实质面积。emoji、紫色状态条、绿色/红色席位与摄影编辑风格互相破坏。
- 数据诚实性也影响高级感：首屏有“交易中”，后面说单次快照；“ROE 连续 5 年 >15%”同时出现最低 14.2%；缺失治理信息却有“治理干净”。放大人物会进一步放大这些矛盾的权威感。这些不能靠免责声明或高级摄影掩盖。

## 2. 用户实际需要的不是更贵的落地页

进入十秒内，应知道：研究对象是什么、此刻最重要的待裁决问题是什么、最强支持与最强反对各是什么、证据是否足够。

进入三十秒内，应能够：切换一个真正不同的思考视角，打开该论点对应底稿，看出处/时间/缺口，回到原论点；无需先理解评分公式或浏览所有人物。

沉浸感服务的是“我主持这场讨论”，而不是“我观看系统替我安排的名人演出”。

## 3. 唯一推荐结构：The Decision Room / 私人投委会

### 桌面主舞台：问题驱动，不是人物轮播驱动

一个视口内保留四层，避免四块卡片：

1. **极薄的研究坐标**：aJay、标的、日期/快照、当前议题编号；城市名称置于远端，明确只是环境选择。
2. **主舞台的三角构图**：左侧 38–44% 为一位主讲人近身黑白肖像；中间偏右 40–46% 为当前待裁决问题和 1 条具体判断；右下/远侧出现反对者的较小裁切肖像与 1 条真正的异议。主次不对称，但二者同时可见。让两人的视线/身体朝向形成场内关系，不是两张证件照贴上背景。
3. **一条极克制的裁决依据**：当前关键数字不超过 3 个，每个有时期/单位；“支持依据 / 最强反证 / 尚缺证据”是同等可达的文字入口。评分不是主标题，不用大圆环。
4. **底边的会议议程**：4–6 个问题（如生意质量、价格、增长兑现、风险、决策条件），当前项清晰。另有“全体视角”入口展示有序姓名/流派索引。默认精选 6–8 位，但所有适用角色可检索；不适用角色合并，不用 0 分制造视觉噪音。

城市摄影提供空间：画面一侧可有窗框/建筑近景形成内外关系，远处城市有真实光照和空气透视。不要将人物硬抠进仿真会议室宣称真实合影；人物与环境可明确采用艺术指导下的编辑式拼接。至少保留一个清晰空间缝隙，避免文字与脸填满全屏。

### 交互：议题保持，视角变化

- 切换人物时保持议题、标的、依据位置；替换其方法论判断及对应证据。不是所有人物都对每个问题有意见，缺席应明确。
- “最强异议”一次点击交换主讲人与反对者，主议题不变。这比自动转场、下一张头像更符合主持者权力。
- 点击证据，打开约 60–70% 宽的研究底稿工作面；主舞台边缘仍保留当前人物/议题的上下文，不遮成廉价小弹窗。底稿可自然纵向滚动，含来源、日期、原值、计算、反例、缺失。
- 底稿保留复制链接/定位章节能力，Esc 关闭并恢复焦点与原状态。完整报告/打印仍是连续文档，不把全部可读内容锁在交互里。
- 城市独立手动切换，保持当前议题、人物、证据状态。摄影变，研究不变。禁止为城市切换伪造不同交易时段的实时性。

### 手机与短屏

不是把全屏桌面同比缩小。手机转为自然纵向的一个议题：主讲人裁切图 → 论点 → 异议 → 证据入口 → 下一议题；不锁滚动。横向人物索引可滑动但有可见文字提示。720px 高度必须能看到论点、异议与依据入口，不靠滚动发现功能。

## 4. 摄影与人物的验收

- 城市至少 4 个，但每一张都要独立构图，不是相同天际线换建筑。优先真实建筑摄影；如使用生成图，必须明显改善曝光、材质、建筑几何、真实镜头感并明确标记来源。
- 夜景不等于高级：允许伦敦阴天、纽约清晨、香港蓝调时段、上海日光中庭；统一的是克制曝光和色彩，而非全部刷成蓝黑。高光要有细节，窗户不得全部等亮，暗部须有层次。
- 主讲人肖像至少 6 位，裁切/尺度/黑位一致但姿态不模板化。不得将一张肖像随意放大到眼睛和嘴变形；姓名与脸必须对应。
- 大肖像必须直接对应其当前分析视角与具体论点；装饰人像不算满足要求。模拟观点标识与姓名区邻近可读，不冒充本人实际发言。
- 图像加载失败时姓名、论点、证据仍完整。前两秒不能只有空白黑底和巨字；背景和人物应有轻量首屏资源。

## 5. 明确否决项

- 更换夜景 + 加大字体 + 多放几张人物卡片，结构仍然是长页面：否决。
- 3D 地球、发光经纬线、粒子、股价跑马灯、旋转圆桌、小头像环、赛博终端、鼠标追光、玻璃卡片雨：否决。它们使投研变成展厅或游戏。
- 强制自动人物/城市轮播、滚轮劫持、每次点击都长时间 cinematic 转场：否决。用户在阅读数字时画面必须稳定。
- 全屏头像只配名人名言，具体论点仍藏在底稿：否决。
- 只显示支持判断，反证需多层打开；用名人脸为低质量规则背书：否决。
- 8 位人物只是同一句结论换口吻；更换人物丢失议题；城市切换改变研究状态：否决。
- 关闭底稿回到首屏、键盘无法操作、移动端有横向页面溢出：否决。

## 6. v0 / 最终的通过标准

### v0 只验结构，不用“还没精修”辩护

1. 首屏即有一个可理解的待裁决问题、主讲人、具体判断、同时可见的真实异议。
2. 主人像必须是构图核心而非装饰配图，城市必须给空间而非仅壁纸。
3. 3 个议题 × 至少 3 个视角可实际切换，切换后信息语义不同且位置稳定。
4. 任一关键论点 1 次操作能打开其证据、来源/日期/缺失；关闭不丢状态。
5. 移除所有 emoji、默认 SaaS 胶囊堆叠、批量卡片墙；精简导航不依赖 hover 才能发现。

### 最终另验

- 在 1440×900、1280×720、390×844 看真实截图；长中文、缺失值、无肖像、证据长文均不破坏层次。
- 正文字号与对比度舒适；摄影最亮处也不会吞字。键盘焦点可见，Esc/Tab 正常；减少动态偏好生效。
- 论点/反证/来源/缺失之间无自相矛盾；来源链接真的通向对应条目，而非所有按钮打开同一个通用资料区。
- 首屏不是免责声明展览，但“模拟视角 / 数据时间 / 未评估”信息始终诚实、可读。
- 随机请一个用户回答“当前判断为什么可能错”，十秒内能从舞台上找到答案。

**总监结论：旧版不达标。推荐重建“问题—主张—异议—证据”的空间组织，不接受只换资产的修饰。新方向须通过实际浏览器评审再认可。**
